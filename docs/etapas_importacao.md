# Etapas da Importação

Caminho: Guia para Administradores > Roteiro de implantação > Importando Dados > Rotina de Importação de Dados de Recursos Humanos > Etapas da Importação

**Etapas da Importação de RH**

A rotina de Importação de RH é dividida nas etapas listadas abaixo:

|  | Etapa 1: Importação de Calendários Fontes de Dados utilizadas: Fonte de Dados de Calendários. Campos utilizados: DESCRICAO_CALENDARIO, DATA_FERIADO, DESCRICAO_FERIADO Nesta etapa são importados registros para o cadastro de Calendários e seus respectivos feriados. No início são inseridos no cadastro de Calendários os novos registros que estão na Fonte de Dadas de Calendários. Não são excluídos Calendários que foram importados anteriormente e que não estejam mais presentes na Fonte de Dados de Calendários. Cada Calendário é composto de um conjunto de Feriados. Um determinado Calendário em sua origem pode sofrer alterações de seus Feriados. Após importar o Calendário, o passo seguinte é a importação dos Feriados de cada Calendário. Realizada a importação, são eliminados os Feriados importados ou cadastrados manualmente que não estejam presentes na Fonte de Dados de Calendários. O campo-chave para importação de Calendários é DESCRICAO_CALENDARIO. O campo-chave para importação de Feriados é DATA_FERIADO. |
|---|---|

|  | Etapa 2: Importação de Empresas Fontes de Dados utilizadas: Fonte de Dados de Clientes e Fonte de Dados de Áreas Campos utilizados: TIPO_COLABORADOR, CODIGO_FORNECEDOR, DESCRICAO_FORNECEDOR, CODIGO_FORNECEDOR, DESCRICAO_FORNECEDOR, SIGLA_EMPRESA (Fonte de Dados de Áreas) e EMPRESA (Fonte de Dados de Áreas). Com a Fonte de Dados de Clientes: Nesta etapa, utilizando a Fonte de Dados de Clientes, são importadas todas as empresas, tanto empresas do próprio grupo, quando empresas fornecedoras. A classificação entre empresa do grupo e empresa fornecedora é feita através do campo TIPO_COLABORADOR. Se ‘EMPREGADO’, cria-se/modifica-se registro apenas no cadastro de Empresas. Se ‘TERCEIRO’, cria-se/modifica-se registro no cadastro de Fornecedores. E utilizando a Fonte de Dados de Áreas são importados os registros, inserindo no cadastro de Empresas quando inexistentes. Em ambos os casos, se o registro for novo será inserido como ativo no cadastro. Para casos de simples atualizações apenas a propriedade Descrição é atualizada. |
|---|---|

|  | Etapa 3: Importação de Unidades de Negócio Fontes de Dados utilizadas: Fonte de Dados de Clientes Campos utilizados: SIGLA_UNIDADE_NEGOCIO, UNIDADE_NEGOCIO, DESC_CALENDARIO_UN_NEGOCIO e CODIGO_FORNECEDOR Nesta etapa são importadas as Unidades de Negócio. Leva-se em consideração a Unidade de Negócio associada a cada Cliente (cadastro de Pessoas). Os campos obrigatórios para o seu cadastro são: Calendário e Empresa. Caso não encontre no cadastro de Calendários o Calendário com o descritivo fornecido por DESC_CALENDARIO_UN_NEGOCIO, o cadastro não será possível. O mesmo para empresa que leva em consideração o campo CODIGO_FORNECEDOR. O campo-chave de uma Unidade de Negócio na Fonte de Dados de Clientes é SIGLA_UNIDADE_NEGOCIO. Caso não seja encontrada uma Unidade de Negócio existente na Fonte de Dados de Clientes que tenha SIGLA_UNIDADE_NEGOCIO igual a uma Unidade de Negócio do cadastro de Unidades de Negócio do Supravizio, é criada uma nova e ativa e Localização igual a descrição da Unidade de Negócio. Os campos que sempre sofrem atualização são: Descrição, Empresa e Calendário. |
|---|---|

|  | Etapa 4: Importação de Prédios Fontes de Dados utilizadas: Fonte de Dados de Clientes. Campos utilizados: SIGLA_UNIDADE_NEGOCIO, PREDIO Nesta etapa são importados os Prédios que compõem cada Unidade de Negócio. Obrigatoriamente um Prédio deve estar associado a uma Unidade de Negócio existente no cadastro de Unidades de Negócio. |
|---|---|

|  | Etapa 5: Importação de Locais Fontes de Dados utilizadas: Fonte de Dados de Clientes. Campos utilizados: SIGLA_UNIDADE_NEGOCIO, PREDIO, LOCAL Nesta etapa são importados os Locais em Prédios de Unidades de Negócio. Obrigatoriamente um Local deve estar associado a um Prédio existente no cadastro de Prédios de uma Unidade de Negócio. |
|---|---|

|  | Etapa 6: Importação de Áreas (Órgãos) Fontes de Dados utilizadas: Fonte de Dados de Áreas. Campos utilizados: SIGLA, ATIVO, DESCRICAO, SIGLA_EMPRESA No início desta etapa, é feita a ativação/inativação das Áreas, de acordo com parâmetro definido no cadastro da rotina de importação e de acordo com o valor do campo ATIVO na Fonte de Dados de Áreas. Após isto, são criadas ou modificadas as áreas no cadastro de Áreas do Supravizio. O campo-chave para esta importação de cadastro de Áreas é o campo SIGLA da fonte de dados que é comparada com a propriedade Sigla de cada Área do cadastro no Supravizio. Para as criações ou modificações, são atualizadas as propriedades Descrição, Sigla e Empresa em uma Área. Os critérios de restrição para a importação de um registro da Fonte de Dados de Áreas para Áreas (Órgãos) são os seguintes: •Incidência de registros nulos ou vazios para: SIGLA, EMPRESA E SIGLA_EMPRESA. •A Empresa associada à Área na Fonte de Dados de Áreas não estar no cadastro de Empresas do Supravizio. •Áreas pai que não estejam presentes como registro na própria Fonte de Dados de Áreas. Para os casos acima, não são importados os registros e suas causas, são indicadas no log de execução da rotina. |
|---|---|

|  | Etapa 7: Importação de Pessoas (Clientes) - Validação de Pessoas ativas. Fontes de Dados utilizadas: Fonte de Dados de Clientes. Campos utilizados: USUARIO_REDE, ATIVO. Nesta etapa são verificadas as definições para ativação/desativação de Pessoas conforme parâmetro definido no cadastro da rotina e verificado valor do campo ATIVO na Fonte de Dados de Clientes. O campo-chave da Fonte de Dados de Clientes para comparações é USUARIO_REDE, sendo comparado com a propriedade UsuarioRede de uma Pessoa. |
|---|---|

|  | Etapa 8: Importação de Pessoas (Clientes) - Atualização de dados. Fontes de Dados utilizadas: Fonte de Dados de Clientes. Campos utilizados: USUARIO_REDE, ATIVO, CARGO, CELULAR_EMPRESA, CELULAR_PARTICULAR, EMAIL, NOME, TELEFONE, TIPO_COLABORADOR, SIGLA_ORGAO, DESCRICAO_ORGAO, CODIGO_FORNECEDOR, SIGLA_UNIDADE_NEGOCIO, PREDIO, LOCAL Nesta etapa são modificadas/inseridas Pessoas no cadastro de Pessoas do Supravizio considerando valores da Fonte de Dados de Clientes. O campo-chave da Fonte de Dados de Clientes para comparações é USUARIO_REDE, sendo comparado com a propriedade UsuarioRede de uma Pessoa. Tanto para inserções quanto para modificações, são atualizadas as propriedades: Cargo, CelularEmpresa, CelularParticular, CulturaCliente (default PT-BR (Português (Brazil))), Email, Nome, NomeAbreviado (igual a Nome por default), Telefone, TipoColaborador, Orgao, Fornecedor e Local. Os critérios de restrição para a importação de um registro da Fonte de Dados de Clientes para Pessoa são os seguintes: •Incidência de registros nulos ou vazios para: NOME, USUARIO_REDE, SIGLA_ORGAO, DESCRICAO_ORGAO e TIPO_COLABORADOR. •TIPO_COLABORADOR só admite dois valores: ‘TERCEIRO’ e ‘EMPREGADO’ •Não pode haver registros duplicados para um mesmo USUARIO_REDE Para os casos acima, não são importados os registros, e os motivos são indicadas no log de execução da rotina. |
|---|---|

|  | Etapa 9: Associação de gestores e configuração de hierarquia das Áreas. Fontes de Dados utilizadas: Fonte de Dados de Áreas. Campos utilizados: SIGLA, GESTOR, SIGLA_ORGAO_PAI Inicialmente é associado um gestor a uma determinada Área através do campo GESTOR da Fonte de Dados de Áreas relacionando uma determinada Pessoa com o UsuarioRede no mesmo valor (comparação em caixa baixa). Neste caso, só será realizada a associação se a Pessoa estiver ativa no cadastro de Pessoas (propriedade Ativo). Caso não seja encontrada no cadastro de Pessoas uma Pessoa com UsuarioRede igual ao valor do campo GESTOR, não será realizada modificação no campo Gestor desta Área. Após isso, para cada Área, é atualizada a Área pai (Órgão pai) relacionando o valor do campo SIGLA_ORGAO_PAI com a Sigla de uma determinada Área presente no cadastro de Áreas do Supravizio. Estas duas operações são realizadas por último, pois necessita de dados atualizados dos próprios cadastros do Supravizio. |
|---|---|
